claude-visual-review · Windows

Set up visual review for Claude Code

Claude Code sends sign-offs, choices, findings and end-of-run reports to the Plannotator Inbox, where you read, pick options and approve when you can. Reports list the changed files as links that open in VS Code, with the diff attached. Your reply goes straight back to the session that asked. This works everywhere: plain sessions, superpowers and BMAD. Review tabs in VS Code open only when you ask for one.

Seeing a message or opening a review never counts as approval. Only Approve does, or your saying so.

Before you start

You need Windows with PowerShell 7, VS Code, Claude Code, git and Python. You need uv only for BMAD projects. Use Claude Code from a VS Code terminal; anywhere else, reviews open in the browser instead.

Rather have your agent do it? Paste the setup prompt into Claude Code and it walks through these steps with you.

Steps

0 of 7 done

  1. Get the project folder

    Clone the public repo into a folder of your choice. To update later: git pull, then run the installer again.

    git clone https://github.com/pmcormier/claude-visual-review
cd claude-visual-review

  2. Run the installer

    It asks which parts you want: Review (always), Methods (how the planning method is picked, BMAD and superpowers), Bmad (the review layer for BMAD workflows) and Fable (a final review of BMAD planning docs; needs access to the Fable model). It installs the rules, the VS Code opener and the PLANNOTATOR_BROWSER setting. -InstallTools also installs whatever is missing: the Plannotator program, the plannotator and visualizer plugins, and the Plannotator WebView extension. It never replaces a file in ~/.claude you changed without asking, and it ends with a Summary of anything left to do. It's safe to run again.

    ./install.ps1 -InstallTools

  3. Add BMAD projects if any

    Needs the Bmad component. Give it each project root that has a _bmad folder. It writes personal (gitignored) review overrides for 17 workflows, plus the Fable final-review lines if you installed Fable, never overwrites existing ones, and checks them with BMAD's own resolver.

    ./install.ps1 -Components Review,Methods,Bmad -BmadProject <project>, <project>

  4. Start fresh

    Close VS Code, open it again and start a new Claude Code session in its terminal. A session started before the install doesn't see the new setting or the new PATH entry.

  5. Set up the Inbox

    Open the Inbox. In Settings > Capabilities, turn on Board and Steps: the rules use Board cards and thread checklists, and both are off by default. Allow notifications when it asks. Leave Settings > Prompts > "Rules for your agents" empty: the rules come from this project. Plannotator adds its own short note to ~/.claude/rules/plannotator-inbox.md by itself. Run the installer again with the components you chose to confirm: it reports Board and Steps.

    plannotator inbox --open
./install.ps1 -Components Review

  6. Check review tabs open in VS Code

    Tabs are only for when you ask for one, but check them once. From the VS Code terminal, this should open a review tab with an Approve button and no "Select an app" dialog. Click Approve and the terminal prints the decision.

    plannotator annotate README.md --gate --json

  7. Check Claude follows the rule

    In the new session, ask for something that needs your sign-off. Claude should send it to the Inbox with Approve and Change, and its file list should use VS Code links. Click one: the browser asks once to open VS Code; tick "Always allow". Answer in the Inbox, and the reply should reach the session without you copying anything.

    Draft a one-page plan for X in docs/, then report it to me in the Inbox for sign-off.

If something's off

You seeCause and fix
"Select an app to open 'open-in-vscode'"The WebView extension's own opener is in use; Windows can't run it. The session started before the install, or settings.json lost the PLANNOTATOR_BROWSER entry. Run the installer again, then start a new session.
Review opens in the browserThe session isn't in a VS Code terminal, or the WebView extension isn't installed. The opener falls back to the browser on purpose.
plannotator not foundInstalled after VS Code started. Terminals inherit VS Code's environment from when it started, so a new terminal isn't enough: close every VS Code window and reopen VS Code. It lives in %LOCALAPPDATA%\plannotator.
No Board cards or checklistsBoard or Steps is off in the Inbox's Settings > Capabilities. The installer reports both.
File links in a report do nothingThe browser blocked VS Code links: click one again and allow it. Plain paths and links inside folding sections don't open (a Plannotator limit, reported); reports use plain lists for that reason.
Replies don't come backThe session started before Plannotator was installed, so it has no Inbox tool. Start a new session.
BMAD ignores itThe project has no overrides. Run ./install.ps1 -BmadProject <root>; the check at the end says whether BMAD reads the policy.

Changing the rules

Want different behaviour? Put it in a rule file of your own, such as ~/.claude/rules/my-review-tweaks.md: Claude loads every file in rules/, and the installer never touches yours, so updates stay a git pull and a rerun. If you edit an installed copy instead, the next install shows the difference and asks before replacing it. Maintaining your own fork? Edit the files in the project folder, run ./install.ps1 again and start a new session, and record the reason in docs/decisions.md.

BMAD has no global settings layer, so each BMAD project needs its own overrides. All of them point at one shared policy file, so one edit reaches every project.
